Create your first MT2 mod

MT2 Mod Framework loads Lua scripts, native plugins and authored content into MMORPG Tycoon 2. Start with a visible greeting, change it, then reload it while the game stays open.

🛟 Need help or found a bug? Get support at support.doodesch.de/modframework.

A greeting in five steps

  1. Open MT2FW-Helper.exe. Select your Steam game and a mod profile, then install the framework. An unknown existing loader must be inspected first.
  2. Choose Create a mod, select Hello MT2, and enter an ID such as yourname.hello. Select the profile's mods directory as the parent.
  3. Start the game normally through Steam. A Hello MT2 window appears. F10 opens the Mods menu. Load a world to see its name in the greeting.
  4. Open the generated main.lua in your text editor. Change "Hello, MT2!" to your own message and save the file.
  5. Open Mods and select Reload beside your mod. The message changes without restarting the game. A syntax error preserves the previous instance and shows the original file and line.

Lua needs no compiler. VS Code with Lua language support is optional. Generated projects include API types and editor settings for completion.

Share the mod

Use Check mod, then Pack mod ZIP in the helper. Write the ZIP outside the source directory. Another player installs that ZIP through the same helper. Include your own source, assets and license; reference game resources instead of redistributing them.

mt2fw new yourname.hello C:/Mods/yourname.hello --template hello
mt2fw check C:/Mods/yourname.hello
mt2fw pack C:/Mods/yourname.hello C:/Mods/hello-1.0.0.zip
mt2fw doctor --game "C:/Steam/steamapps/common/MMORPG Tycoon 2"

Small, useful recipes

Show a setting and a world event

mt2.config.define("greeting", {
    type = "string", default = "Hello, MT2!", label = "Greeting"
})

mt2.events.on("world_ready", function(event)
    mt2.log.info("World ready: " .. event.name)
end)

mt2.ui.window("My greeting", function()
    mt2.ui.text(mt2.config.get("greeting"))
end)

Read an object explicitly

mt2.ui.window("Selected object", function()
    if mt2.world.status().loaded and mt2.ui.button("Read selection") then
        local object = mt2.objects.selected()
        if object then mt2.log.info("Selected UID: " .. object.handle.uid) end
    end
end)

Declare ui, world.read and objects.read capabilities. Read large lists on demand. Handles contain an epoch and an exact string UID; keep the handle intact instead of converting its UID to a floating-point number.

Keep profile and world data

mt2.events.on("start", function()
    local count = mt2.storage.get("starts", 0)
    mt2.storage.set("starts", count + 1)
end)

mt2.events.on("world_ready", function()
    local value = mt2.storage.get("visits", 0, "world")
    mt2.storage.set("visits", value + 1, "world")
end)

Profile data persists independently. World data is associated with a confirmed game save. Reloading code preserves completed world actions; it does not rewind a save.

Use mt2.objects.persist(handle) for a mod-owned reference to a root-world building. Store the returned string in world data, then use mt2.objects.resolve(id) after loading. The framework captures the saved region and building position and checks the saved identity before rebinding. Session handles are invalid after a world change.

Bind a key

-- SDL scancode 66 is F9. Declare the input capability.
mt2.input.bind("show_message", 66, function()
    mt2.log.info("My shortcut was pressed")
end)

F10 belongs to the framework. Conflicting mod shortcuts report their current owner.

Submit a world action

local pending
mt2.events.on("world_ready", function()
    -- Use an owned, buildable position and a registered definition.
    pending = mt2.actions.place("yourname.scenery:obelisk", 0, 0, 0)
end)
mt2.events.on("action_completed", function(result)
    if pending and result.id == pending.id then
        mt2.log.info(result.status)
        if result.cause ~= "" then mt2.log.warn(result.cause) end
    end
end)

Declare objects.write and use singleplayer or shared. A returned accepted request is queued. Wait for confirmed. Investigate unknown before taking another action; it must not be automatically replayed.

API reference

Camera and time

-- Declare ui, world.read, camera and time.write; use singleplayer.
mt2.ui.window("World controls", function()
    if not mt2.world.status().loaded then return end
    local view = mt2.camera.get()
    mt2.ui.text("Camera distance: " .. view.distance)
    if mt2.ui.button("Pause") then mt2.time.set(true, 1) end
    if mt2.ui.button("Resume") then mt2.time.set(false, 1) end
    if mt2.ui.button("Focus here") then
        mt2.camera.focus(view.focus_x, view.focus_y, view.focus_z, 100)
    end
end)

Import static scenery

Choose Import GLB in the helper. Drag the preview to inspect orientation, enter a scale and refresh. The importer reports triangle count, materials, textures, bounds and unsupported features before exporting a separate content package. Place that package in the profile's mods directory and restart the game. Its model is registered in the native Scenery catalog. Each content ID and generated resource name belongs to that mod.

Version 1 supports static triangles, node transforms, normals, UVs, vertex colors, base colors and embedded PNG/JPEG textures. Skins, animation, morphs, sparse accessors, compressed geometry and unsupported material extensions report an import error. Metallic and roughness factors map to diffuse materials with a warning. The native catalog uses binary ModelV1 files; the editable VMD remains alongside the generated VMB.

The generated content manifest registers the package automatically. To combine Lua behavior and content in one package, set its manifest type to lua, use main.lua as the entry, retain the content capability, and register the generated definitions once at startup:

mt2.content.register(require("definitions"))

The generated definitions.lua contains the exact resource names. Registrations are prepared before activation. Lua packages that register content require restarting for changes, just like content packages.

Native plugins

Use the native template and the bundled mt2fw/plugin.h. Export MT2FW_PluginQuery, MT2FW_PluginLoad and MT2FW_PluginShutdown. The host struct carries its size and ABI version. Subscribe to named events and use JSON requests for the same capability-checked services as Lua.

With Visual Studio C++ and CMake installed, build from the generated native mod directory. The DLL is written beside mod.json, ready for checking and packaging:

cmake -S . -B build -A x64
cmake --build build --config Release
mt2fw check .

Measure the host request buffer first; that call does not execute the operation. Supply the returned capacity for the execution call. Strings are UTF-8. Never let C++ exceptions cross the ABI or free memory owned by the other module. Native plugins remain loaded until the game exits.

Troubleshooting

StateAction
Unsupported game buildUse Diagnostics to read the executable hash. Wait for an adapter for that build. Do not force a signature match.
Reload rejectedFix the reported file and line, then reload again. The previous instance stays active if replacement preparation fails.
Mod disabled after callback failureRead the original exception, fix the script and reload. Other independent mods continue running.
Dependency unavailableInstall and enable the named dependency at a compatible version, then restart.
Expired handleRead the selection or query the current world again. Do not carry live object handles between worlds.
Action result unknownInspect the actual world and original error. Do not replay the same mutation automatically.
Missing content for a saveRestore the matching content package before loading. The framework must preserve the save.

Lua callbacks have an instruction budget and each Lua state has a memory budget. Long-running work belongs outside frame callbacks. Direct process execution and arbitrary native Lua libraries are unavailable through the regular Lua API.

Versions and compatibility

Declare api_version: "1.0.0". Stable APIs are additive within a major version. The manifest supports exact dependency versions, caret ranges and minimum ranges. Keep package IDs stable when releasing updates.

local mods cannot request world changes. shared mods require matching packages, hashes and shared settings on all peers. singleplayer mods cannot activate in a multiplayer session. The separate multiplayer bridge must pass its two-account acceptance before shared writes become available.
